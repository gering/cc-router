# Clear Dependabot alert #1: mcp below 1.30.0 in the Semgrep pin set

## Goal
Dependabot alert #1 (medium, created 2026-10-21) flags `mcp==1.29.0` in
`.github/semgrep-requirements.txt`: "MCP Python SDK: Unbounded Session
Accumulation in StreamableHTTP Transport Enables Resource Exhaustion", fixed in
1.30.0. The file is the hash-pinned Semgrep CE install for
`.github/workflows/security.yml` (PR #23); `mcp` comes in transitively via
`semgrep==1.182.0`. It runs in CI only and ships nothing, but the alert should
close with the root cause fixed.

## Approach
- Prefer a Semgrep release whose own dependency range already resolves
  `mcp>=1.30.0`; check the Semgrep changelog/PyPI metadata first.
- If none does, add `mcp>=1.30.0` as an explicit constraint to the compile
  input instead of hand-editing the lock lines.
- Regenerate with the command in the file header
  (`uv pip compile … --generate-hashes --python-version 3.12 --python-platform linux`),
  extending the header if a constraint is added so the next regeneration keeps it.
- Never hand-edit hashes.

## Acceptance
- `.github/semgrep-requirements.txt` pins `mcp` at 1.30.0 or later, all hashes
  generated by `uv pip compile`.
- The security workflow is green on the PR (Semgrep installs and scans, gitleaks
  passes); `make check` still passes.
- Dependabot alert #1 is closed by the merge (not dismissed).
